# 家校沟通话术助手 MVP Spec

## Why
一线教师在面对家长质疑/投诉时缺乏标准化、专业化的回应话术参考，容易因措辞不当引发矛盾升级。本产品通过 AI 生成 + 内置话术库，帮助老师快速产出 1-3 条安全、有策略的家长回复话术，并沉淀沟通记录，形成可追溯的家长沟通档案。

## What Changes
- 新增账号系统：邮箱+密码注册/登录/退出，每个用户数据隔离
- 新增班级管理：创建/列表/编辑/删除班级（含年级下拉 1-6）
- 新增学生管理：手动添加/编辑/删除、标签管理（逗号分隔字符串存储）、批量文本导入
- 新增沟通记录：记录沟通事件（学生/家长消息/回复/结果）、列表、详情、结果编辑
- 新增 AI 话术生成（核心）：粘贴家长消息→选学生→调用 DeepSeek 返回结构化 JSON（1-3 条话术 + 策略 + 风险），可编辑保存
- 新增内置话术库：预置 20 个常见场景（含家长表述/话术模板/策略/风险），占位符替换，注入 DeepSeek 系统提示词
- 新增页面：登录注册页、工作台、班级管理、学生列表/详情、沟通记录、话术生成页
- 新增主题与皮肤系统：内置多套主题（默认/护眼/暗色等），用户可切换并记忆
- 新增微动效设计：页面过渡、按钮反馈、列表项入场、生成中加载等轻量动效
- 新增励志正能量提示：工作台、话术生成页等特定位置展示鼓励话语
- 非功能：bcrypt 密码加密、用户级数据隔离、隐私提示（未成年人信息）、双模式 DB（本地直连调试 + Cloudflare Hyperdrive 部署）
- 新增全量功能测试：开发完成后按专业测试流程进行全量功能测试（含正向/异常/边界/隔离/兼容性），保留测试数据
- 新增页面优化：基于测试反馈进行 UI/UX 与性能优化

## Impact
- Affected specs: 全新项目，无既有 spec 受影响
- Affected code: 全新代码库
  - 前端：**Next.js（React）+ App Router + Tailwind CSS**，B2C 风格 UI，配合 **Framer Motion** 实现微动效
  - 后端：**Next.js API Routes**（Route Handlers），本地 Node 运行时调试，生产运行于 Cloudflare 运行时
  - 数据库：**MySQL**（外部实例 121.224.76.39:8001，库名 jiaxiao，表待建），本地开发直连，生产通过 **Cloudflare Hyperdrive** 连接池
  - 认证：自建，bcrypt 密码哈希 + JWT（httpOnly Cookie）会话
  - AI：**DeepSeek API**（deepseek-chat），系统提示词内置话术库与策略
  - 部署：**Cloudflare Pages**（`@cloudflare/next-on-pages` 适配），配合 Hyperdrive 绑定
  - 主题：CSS 变量 + Tailwind dark/light + 主题上下文，localStorage 持久化

## ADDED Requirements

### Requirement: 账号系统
系统 SHALL 提供邮箱+密码注册、登录、退出功能，每个用户拥有独立数据空间。密码 SHALL 经 bcrypt（cost≥10）加密存储，会话使用 JWT（HS256，有效期 7 天）置于 httpOnly Cookie。

#### Scenario: 注册成功
- **WHEN** 用户提交有效邮箱（格式校验）+ 密码（≥6 位）
- **THEN** 密码 bcrypt 哈希后写入 users 表（email 唯一约束，重复注册返回 409），签发 JWT 写入 httpOnly Cookie，进入工作台

#### Scenario: 登录成功
- **WHEN** 用户提交邮箱+密码，bcrypt.compare 校验通过
- **THEN** 签发 JWT 写入 httpOnly Cookie，进入工作台

#### Scenario: 登录失败
- **WHEN** 邮箱不存在或密码错误
- **THEN** 返回统一错误"邮箱或密码错误"（不区分两者，防枚举）

#### Scenario: 数据隔离
- **WHEN** 用户 A 调用任意业务 API
- **THEN** 仅返回 user_id = A 的数据（API 层从 JWT 解析 user_id 并强制 `WHERE user_id = ?` 过滤），不泄露其他用户数据

#### Scenario: 退出登录
- **WHEN** 用户点击退出
- **THEN** 清除 JWT Cookie（Set-Cookie maxAge=0），跳转登录页

### Requirement: 班级管理
系统 SHALL 支持用户创建多个班级，每个班级包含名称（必填，≤30 字）和年级（1-6 年级下拉）。

#### Scenario: 创建班级
- **WHEN** 用户填写班级名称 + 选择年级并提交
- **THEN** 在当前用户名下创建班级（写入 user_id），出现在班级列表

#### Scenario: 编辑班级
- **WHEN** 用户修改班级名称或年级（API 校验班级归属于当前 user_id）
- **THEN** 更新成功，列表同步刷新

#### Scenario: 删除班级（确认）
- **WHEN** 用户点击删除并确认弹窗
- **THEN** 删除班级及其关联学生/沟通记录（外键 ON DELETE CASCADE），列表移除该项

### Requirement: 学生管理
系统 SHALL 支持手动添加学生、批量文本导入、编辑、删除。学生标签以逗号分隔字符串存入 students.tags 字段（如"性格内向,近期成绩下滑"）。

#### Scenario: 手动添加学生
- **WHEN** 用户填写姓名（必填，≤20 字）+ 性别（选填：男/女）+ 标签（逗号分隔）并提交
- **THEN** 学生创建成功并归入指定班级，tags 字段存原始字符串

#### Scenario: 批量导入
- **WHEN** 用户粘贴多行文本并提交，每行格式 `姓名,性别,标签1;标签2`（性别与标签可空，标签内多标签用分号分隔）
- **THEN** 系统按行解析：trim 后跳过空行；姓名缺失的行跳过；性别非"男/女"视为空；标签分号拆分后逗号拼接存入 tags。批量插入并返回成功/跳过条数

#### Scenario: 编辑学生
- **WHEN** 用户修改学生姓名/性别/标签
- **THEN** 更新成功（校验归属），列表同步

#### Scenario: 删除学生（确认）
- **WHEN** 用户确认删除
- **THEN** 删除学生及关联沟通记录（CASCADE），列表移除

### Requirement: 沟通记录
系统 SHALL 记录每次沟通事件，字段：id、user_id、student_id（可空）、parent_message（家长消息）、reply（回复话术，多条以换行分隔）、strategy（策略提示）、risks（风险提示）、result（结果文本，可空）、created_at、updated_at。

#### Scenario: 保存沟通记录
- **WHEN** 用户在话术生成页选择学生（可选）+ 家长消息 + 生成/编辑回复 + （可选）结果并保存
- **THEN** 创建一条沟通记录，关联当前 user_id 与所选 student_id

#### Scenario: 查看列表
- **WHEN** 用户进入沟通记录页（可按班级/学生筛选）
- **THEN** 显示列表项：时间、学生姓名（无则显示"未关联"）、家长消息摘要（前 30 字）

#### Scenario: 查看详情
- **WHEN** 用户点击列表项
- **THEN** 显示完整家长消息、回复话术、策略提示、风险提示、结果文本

#### Scenario: 编辑结果字段
- **WHEN** 用户在详情页编辑结果文本框并保存
- **THEN** 更新 result 字段，记录后续进展

### Requirement: AI 话术生成（核心）
系统 SHALL 接收家长消息 + 可选学生上下文，调用 DeepSeek API（deepseek-chat），系统提示词内置 20 场景话术库与沟通策略，要求模型返回结构化 JSON：`{scripts: string[1-3], strategy: string, risks: string[]}`。老师可编辑后保存为沟通记录。

#### Scenario: 生成话术
- **WHEN** 用户粘贴家长消息 + 选择学生（可选）+ 点击"生成话术"
- **THEN** 后端 Route Handler 组装系统提示词（含话术库）+ 用户消息（选中学生时注入"学生姓名/性别/标签"上下文），调用 DeepSeek，解析 JSON 返回 1-3 条话术、策略提示、风险提示；解析失败时降级为纯文本展示

#### Scenario: 加载动效
- **WHEN** 生成请求进行中
- **THEN** 按钮显示加载态（spinner + 文案"正在生成话术…"），结果区淡入展示

#### Scenario: 编辑并保存
- **WHEN** 用户编辑生成的话术（textarea 可改每条话术/策略/风险）并点击保存
- **THEN** 保存编辑后内容为沟通记录，关联学生，可在沟通记录中查看

### Requirement: 内置通用话术库
系统 SHALL 预置 20 个常见家长质疑/投诉场景，每场景含家长常见表述、回复话术模板（含占位符）、沟通策略、风险提示，作为 DeepSeek 系统提示词的一部分。

20 场景清单：1.孩子被欺负 2.作业太多 3.老师偏心 4.成绩下滑 5.座位问题 6.批评不当 7.班级管理争议 8.调座位诉求 9.作业没批改 10.课堂纪律/孩子被影响 11.老师态度冷漠 12.孩子被孤立 13.罚站/体罚质疑 14.作业没完成被批评 15.成绩排名压力 16.老师换人不满 17.孩子丢东西 18.放学太晚 19.补课/收费质疑 20.孩子不想上学

占位符：`{学生姓名}`、`{具体行为}`、`{家长称呼}` 等，生成时按学生上下文替换。

### Requirement: 主题与皮肤系统
系统 SHALL 内置至少 3 套主题（默认浅色 / 护眼绿 / 暗色），用户可在设置中切换，选择持久化到 localStorage 并即时应用。

#### Scenario: 切换主题
- **WHEN** 用户在设置/顶栏切换主题
- **THEN** 通过 CSS 变量即时切换配色，刷新后保持上次选择

### Requirement: 微动效设计
系统 SHALL 在关键交互处加入轻量微动效（基于 Framer Motion），不喧宾夺主：页面路由过渡淡入、按钮点击缩放反馈、列表项入场错位淡入、生成结果区淡入上滑、卡片 hover 轻微上浮。

#### Scenario: 列表入场
- **WHEN** 班级/学生/记录列表数据加载完成
- **THEN** 列表项依次错位淡入（stagger，间隔约 50ms）

### Requirement: 励志正能量提示
系统 SHALL 在工作台、话术生成页等特定位置展示随机励志/正能量鼓励话语（内置文案池，每次进入或刷新随机一条），面向教师群体，传递正向价值。

#### Scenario: 工作台鼓励语
- **WHEN** 用户进入工作台
- **THEN** 顶部或卡片区展示一条随机鼓励话语（如"每一句用心的沟通，都在拉近家校的距离"）

### Requirement: 页面与导航
系统 SHALL 提供登录注册页、工作台、班级管理页、学生列表/详情页、沟通记录页、话术生成页、设置页（主题切换），B2C 风格 UI、桌面优先简单响应式。

#### Scenario: 工作台概览
- **WHEN** 用户登录后进入工作台
- **THEN** 显示班级数量、学生总数、最近沟通记录列表、快捷入口、鼓励语

### Requirement: 非功能需求
系统 SHALL：bcrypt 密码加密；API 层 user_id 过滤实现数据隔离；学生管理与话术生成页展示隐私提示；DB 支持双模式——本地开发直连 MySQL，生产经 Cloudflare Hyperdrive 连接（同一 DB 工具函数按环境切换）。

#### Scenario: 双模式 DB 连接
- **WHEN** 本地 `npm run dev`
- **THEN** 使用 `MYSQL_URL` 直连外部 MySQL（121.224.76.39:8001/jiaxiao）
- **WHEN** 部署到 Cloudflare Pages
- **THEN** 使用 Hyperdrive binding 连接同一 MySQL 实例

#### Scenario: 隐私提示展示
- **WHEN** 用户进入学生管理或话术生成页面
- **THEN** 界面展示隐私提示："班级学生信息涉及未成年人个人信息，请老师自行妥善管理数据，本产品仅保存必要信息"

### Requirement: 全量功能测试
系统 SHALL 在所有功能开发完成后，按专业测试流程进行全量功能测试，覆盖正向用例、异常用例、边界条件、数据隔离、主题/动效/鼓励语、响应式兼容性，测试过程中产生的数据 SHALL 保留（不清库），并记录缺陷与修复。

#### Scenario: 正向测试
- **WHEN** 按验收闭环用例执行（注册→建班→加学生→打标签→生成话术→保存记录→查看档案→切换班级隔离）
- **THEN** 全流程通过，数据正确落库并展示

#### Scenario: 异常与边界测试
- **WHEN** 测试重复注册、错误密码登录、空表单提交、超长输入、批量导入格式错误行、未选学生保存记录、AI 接口超时/返回非 JSON 等
- **THEN** 系统给出合理错误提示，不崩溃、不泄露数据

#### Scenario: 测试数据保留
- **WHEN** 测试阶段结束
- **THEN** 测试创建的账号/班级/学生/沟通记录数据保留在库中，不执行清库操作

### Requirement: 页面优化
系统 SHALL 基于测试反馈进行 UI/UX 与性能优化：视觉一致性、间距与对齐、加载与空状态、错误提示友好度、首屏加载性能。

#### Scenario: 空状态与加载态
- **WHEN** 列表无数据或加载中
- **THEN** 展示友好的空状态插图/文案与骨架/加载态，而非空白
